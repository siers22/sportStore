# Движение — магазин спортивного инвентаря

Учебный интернет-магазин на ASP.NET Core MVC. Покупатели просматривают каталог и оформляют заказы, продавцы управляют товарами и заказами, администратор обрабатывает жалобы. Оплата демонстрационная: реальные деньги не списываются.

## Запуск в Visual Studio

1. Установите Visual Studio 2022 версии 17.8 или новее (либо Visual Studio 2026) с компонентом **ASP.NET and web development** и .NET 8 SDK.
2. Скачайте или клонируйте репозиторий. В Visual Studio выберите **Файл → Открыть → Проект или решение** и откройте `SportStore.sln` из корня проекта. Не открывайте папку в режиме «Представление папок» и не запускайте `Program.cs` отдельно.
3. Дождитесь восстановления пакетов NuGet. Выберите проект `SportStore` как запускаемый и нажмите **F5**.
4. Откройте `http://localhost:5080`, если браузер не открылся автоматически.

Для первого восстановления NuGet-пакетов нужен интернет. PostgreSQL и Docker для обычного запуска не требуются. Подробности: [VISUAL_STUDIO.md](VISUAL_STUDIO.md).

## Запуск из терминала

При установленном .NET 8 SDK выполните из корня проекта:

```bash
dotnet run --project SportStore/SportStore.csproj --launch-profile SportStore
```

Необязательный запуск через Docker: `docker compose up --build -d`. Остановка: `docker compose down`.

## Технологии и данные

- ASP.NET Core MVC, Razor Views, C# и .NET 8.
- Entity Framework Core и SQLite. База `sportstore.db` создаётся автоматически при первом запуске и хранится рядом со сборкой приложения.
- ASP.NET Core Identity для регистрации, входа и ролей.

Исходники находятся в `SportStore/`: серверный код — в `Controllers`, `Data`, `Models`, `Services`, интерфейс — в `Views` и `wwwroot`. Каталог содержит 12 демонстрационных товаров. При запуске приложение добавляет недостающие поля модерации в существующую SQLite-базу. Полноценные миграции EF Core пока не добавлены.

## Сценарий проверки

1. Войти как покупатель и добавить в корзину товары двух продавцов.
2. На оформлении заказа проверить, что неверный телефон не принимается, затем указать номер в формате `+7 900 000-00-00` или `8 900 000-00-00` и проверить баланс и историю операций.
3. Войти как продавец и изменить статус своего заказа.
4. Войти как покупатель и отправить жалобу на товар.
5. Войти как администратор и рассмотреть жалобу. При скрытии товара указать причину.
6. Войти как продавец, увидеть причину, исправить товар и сохранить его. Товар попадёт на проверку и останется скрытым из каталога.
7. Войти как администратор и одобрить исправленный товар, чтобы он снова появился в каталоге.
8. На странице пользователей заблокировать демонстрационного покупателя с причиной, проверить сообщение при входе покупателя и разблокировать его.

Это учебный локальный проект. Доставка представлена адресом и статусом заказа; внешних служб доставки и платёжных систем нет. Демонстрационные пароли предназначены только для локальной проверки.
