# Движение — магазин спортивного инвентаря

Учебный интернет-магазин на ASP.NET Core MVC. Покупатели просматривают каталог и оформляют заказы, продавцы управляют товарами и заказами, администратор обрабатывает жалобы. Оплата демонстрационная: реальные деньги не списываются.

## Запуск в Visual Studio

1. Установите Visual Studio 2022 версии 17.8 или новее (либо Visual Studio 2026) с компонентом **ASP.NET and web development** и .NET 8 SDK.
2. Скачайте или клонируйте репозиторий. В Visual Studio выберите **Файл → Открыть → Проект или решение** и откройте `SportStore.sln` из корня проекта. Не открывайте папку в режиме «Представление папок» и не запускайте `Program.cs` отдельно.
3. Дождитесь восстановления пакетов NuGet. Выберите проект `SportStore` как запускаемый и нажмите **F5**.
4. Откройте `http://localhost:5080`, если браузер не открылся автоматически.

Для первого восстановления NuGet-пакетов нужен интернет. PostgreSQL и Docker для обычного запуска не требуются. Подробности: [VISUAL_STUDIO.md](VISUAL_STUDIO.md).

## Запуск из терминала

При установленном .NET 8 SDK выполните из корня проекта:

```bash
dotnet run --project SportStore/SportStore.csproj --launch-profile SportStore
```

Необязательный запуск через Docker: `docker compose up --build -d`. Остановка: `docker compose down`.

## Технологии и данные

- ASP.NET Core MVC, Razor Views, C# и .NET 8.
- Entity Framework Core и SQLite. База `sportstore.db` создаётся автоматически при первом запуске и хранится рядом со сборкой приложения.
- ASP.NET Core Identity для регистрации, входа и ролей.

Исходники находятся в `SportStore/`: серверный код — в `Controllers`, `Data`, `Models`, `Services`, интерфейс — в `Views` и `wwwroot`. Каталог содержит 12 демонстрационных товаров. Для базы предыдущей версии при запуске автоматически добавляются поля модерации, поле фото товара и таблица пополнений без удаления существующих данных. Полноценные EF-миграции для дальнейшего развития схемы пока не добавлены.

## Демонстрационные аккаунты

| Роль | Логин | Пароль |
| --- | --- | --- |
| Администратор | `admin` | `Admin123!` |
| Продавец «Тропа» | `trail` | `Demo123!` |
| Продавец «Арена» | `arena` | `Demo123!` |
| Покупатель | `buyer` | `Demo123!` |

Демоаккаунты входят по коротким логинам. Прежние email вида `admin@sport.local` также работают. В существующей базе логины обновляются при запуске; пользователи, пароли, баланс и заказы сохраняются. Обычные зарегистрированные пользователи продолжают входить по email.

У покупателя есть виртуальная карта с балансом 100 000 ₽. При регистрации новому покупателю также выдаётся демонстрационная карта.

## Сценарий проверки

1. Войти как покупатель и добавить в корзину товары двух продавцов.
2. На оформлении заказа проверить, что неверный телефон не принимается, затем ввести номер с маской, например `+7 (900) 123-45-67` и проверить баланс и историю операций.
3. Войти как продавец и изменить статус своего заказа.
4. Войти как покупатель и отправить жалобу на товар.
5. Войти как администратор и рассмотреть жалобу. При скрытии товара указать причину.
6. Войти как продавец, увидеть причину, исправить товар и сохранить его. Товар попадёт на проверку и останется скрытым из каталога.
7. Войти как администратор и одобрить исправленный товар, чтобы он снова появился в каталоге.
8. На странице пользователей заблокировать демонстрационного покупателя с причиной, проверить сообщение при входе покупателя и разблокировать его.

Это учебный локальный проект. Доставка представлена адресом и статусом заказа; внешних служб доставки и платёжных систем нет. Демонстрационные пароли предназначены только для локальной проверки.

## Фото товаров и пополнение карты

Продавец может загрузить, заменить или удалить фото при создании и редактировании товара. Поддерживаются JPG, PNG и WebP до 5 МБ, есть предпросмотр. Фото показывается в каталоге, на странице товара и в корзине. Сервер проверяет размер и сигнатуру файла. Фотографии хранятся в `product-images` рядом с базой; для резервного копирования и переноса сохраняйте и базу, и эту папку. Через `SPORTSTORE_DATA_DIR` можно задать постоянную папку для этих данных.

Покупатель открывает **Карта → Пополнить карту**. На экране — сумма, тестовые реквизиты и детали перевода; после подтверждения открывается чек, а пополнение появляется в общей истории со списаниями. Сумма — от 100 до 1 000 000 ₽, максимум две цифры после запятой; максимальный итоговый баланс — 9 999 999,99 ₽. Повторная отправка одной формы не начисляет средства второй раз.

Для демонстрации: номер `4242424242424242`, будущий срок действия (например, `12/35`), CVC `123`. Реальные реквизиты вводить не нужно: платёжного провайдера нет, банковские данные в базе не сохраняются.

Телефон при оформлении заказа собирается по маске `+7 (900) 123-45-67`: пользователь вводит цифры, скобки, пробелы и дефисы добавляются автоматически. Можно вставить полный номер с `+7`, `7` или `8`, а также 10 цифр без кода страны. Поддерживаются удаление и исправление в середине номера. Сервер принимает только полностью заполненный формат `+7 (XXX) XXX-XX-XX`.

## Проверка изменений

После `dotnet build SportStore/SportStore.csproj` можно выполнить `python3 tests/verify_flows.py` (Python 3.9+ и .NET 8). Если `dotnet` не в PATH, укажите `--dotnet /полный/путь/dotnet`. Скрипт запускает приложение на свободном локальном порту и использует временную копию старой базы либо новую временную базу. Он проверяет обновление схемы, фото, пополнения, защиту от повторного начисления, телефон и доступ по ролям. Рабочая база не изменяется.

Проверка маски телефона (Node.js 18+): `node --test tests/phone-mask.test.cjs`.
